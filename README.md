# 📊 End-to-End Telco Customer Churn Prediction

A full-stack Machine Learning application that predicts whether a telecommunications customer is likely to churn. The project demonstrates a complete **MLOps pipeline** including model training, experiment tracking, containerization, and automated cloud deployment.

## 🏗 Architecture
The application is built using a microservices architecture wrapped in Docker containers:

1.  **Machine Learning:** A **CatBoostClassifier** trained on customer demographics and service data.
2.  **Tracking:** **MLflow** server (hosted on EC2) tracks model accuracy, F1-scores, and parameters during CI/CD runs.
3.  **Backend (API):** **FastAPI** serves the model predictions via REST endpoints.
4.  **Frontend:** **Streamlit** provides an interactive dashboard for users to input data and visualize churn risk.
5.  **Infrastructure:**
    *   **AWS EC2:** Hosts the application (Ubuntu).
    *   **AWS ECR:** Stores the Docker images.
    *   **GitHub Actions:** Handles Continuous Integration & Deployment (CI/CD).

## ⚙️ Local Setup

To run this application locally on your machine:

1.  **Clone the repository:**
    ```bash
    git clone https://github.com/your-username/customer-churn-prediction.git
    cd customer-churn-prediction
    ```

2.  **Create an `.env` file:**
    Create a file named `.env` in the root directory:
    ```ini
    AWS_ACCOUNT_ID=123456789
    AWS_REGION=us-east-1
    ```

3.  **Run with Docker Compose:**
    ```bash
    docker-compose -f docker-compose.prod.yaml up --build
    ```

4.  **Access the Services:**
    *   Frontend: `http://localhost:8501`
    *   API Docs: `http://localhost:80/docs`
    *   MLflow: `http://localhost:5000`

## 🔄 CI/CD Pipeline (GitHub Actions)

The pipeline is defined in `.github/workflows/deploy.yml`. Every time code is pushed to the `main` branch, the following steps occur automatically:

1.  **Train Model:**
    *   Runs `ml/train.py`.
    *   Attempts to connect to the remote MLflow server to log metrics.
    *   Saves the model artifact (`final_model.cbm`) locally for the build step.
2.  **Build Docker Images:**
    *   Builds the **API** image (including the new model).
    *   Builds the **Frontend** image.
3.  **Push to AWS ECR:**
    *   Tags and uploads images to the private Elastic Container Registry.
4.  **Deploy to EC2:**
    *   Connects to EC2 via SSH.
    *   Pulls the new images.
    *   Restarts the containers using `docker-compose`.
